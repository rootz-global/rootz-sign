Verify a signed document

Checks that a document is unaltered and was signed by whoever controls its domain. Everything happens in your browser.

Paste mode — nothing leaves your browser except a DNS lookup

This mode is fully local. We never see the document.

URL mode

A browser cannot fetch most other sites directly, so this mode asks our server to retrieve the two files. The signature check and the DNS lookup still happen here in your browser — but if you would rather we never touched the document at all, use paste mode.

How this works, so you can check our work

Four things get checked, and each can fail independently:

  1. Content unaltered. The signed region is normalised (line endings, trailing spaces, Unicode form) and hashed with SHA-256. That must equal the hash in the proof. Wording, punctuation and numbers are untouched by normalisation — if any of those changed, the hash changes.
  2. Key fetched independently. The public key is read from a DNS TXT record at _ai-authority.<domain> using Cloudflare's DNS-over-HTTPS. Using the key inside the document to check the document would prove nothing — a forger would simply include their own.
  3. Signature valid. Verified locally with WebCrypto. The signature covers the content hash together with the domain, key id and timestamp, so a valid signature cannot be lifted off one document and attached to another.
  4. Key authorised when signed. Checked against the validity window in DNS — at the moment of signing, never “is this key still valid today”. A key retired in 2028 signed perfectly good documents in 2026, and those must keep verifying.

What a pass does not tell you: nothing about whether the content is true, current, or any good. Provenance is not accuracy. It tells you who stood behind these exact words, and that they have not changed since.
